# PR #15：CI 环境与测试隔离修复

本轮仅修复审阅分支的 CI，不调整产品版本，不合并、发行或启动 Minecraft。

## 失败原因与改动

- `setup-java@v5` 的完整构建版本匹配会比较 build metadata；`21.0.13+9` 与供应方返回的 `21.0.13+9.0.LTS` 不相等。固定为已返回的完整版本，保留 Temurin、Java 21 和原生架构检查。依据为 [setup-java 的匹配实现](https://github.com/actions/setup-java/blob/v5/src/util.ts) 及原失败作业。
- 可移植 Core 服务夹具在构造工厂时提前选择生产原生凭据，Linux 尚无适配器，导致大量业务断言没有执行。保留原有双参数生产入口，新增显式 `ICredentialStore` 注入重载；57 处 Core 和 3 处 Headless 服务夹具通过 `tests/Shared/TestPlatformServices.cs` 使用各自独立的内存存储，不访问当前用户 DPAPI/Keychain。原生适配器和真实旧账户测试保留原入口。
- 新回归核对显式存储组合、字节隔离及不生成原生凭据文件；Linux 默认生产入口仍须抛出 `PlatformNotSupportedException`，没有新增 Linux 产品发行或明文凭据回退。
- Headless 页面初始化还会读取内存信息；共享夹具显式提供总量 16 GiB / 可用 8 GiB 的固定测试快照，避免进一步调用不支持 Linux 的 `NativeMemoryInfo`。生产内存适配器未变，既有测试需要其它内存情景时仍可显式覆盖。
- Conduit Build 另有两项旧 aria2 RPC 夹具仍期待 `forcePause` / 直接 `unpause`。按现有生产实现补齐暂停后连续 idle 状态、移除旧请求组再以同 GID/路径及 `continue=true` 续传的响应与断言。未改 aria2 产品协议、未移除所有权校验或跳过失败用例；同一 RPC 回归文件也纳入共享 Core 测试。
- Windows 英文 runner 的 Java 启动器将不能映射到系统 ANSI 代码页的中文源码路径变为 `??`。Java 夹具改用工作目录内的相对源码路径，stdout/stderr 明确为 UTF-8；通用 OS argv 的完整中文、引号、空值、换行和 shell 字面量断言使用同测试程序集的受控 .NET 子进程。Java 的管道、环境变量、超时、取消、脱离存活和关闭上下文仍用原生 Java 子进程验证，未改系统区域设置，也不将 OS argv 测试当作 Java 任意 Unicode 命令行兼容性保证。[Java 21 发布说明](https://www.oracle.com/java/technologies/javase/21-0-9-relnotes.html)记录了该 ANSI 转换边界。

## 本地验证

通过注册的 `control/dev.py` 与 `Invoke-Dev.ps1` 执行 Windows x64 / Release：构建 0 警告、0 错误；Core **905 通过、11 条件跳过、0 失败，共 916**，包含五项 aria2 RPC 回归及显式凭据注入检查。使用与 CI 相同的 Windows 类别筛选，未启用真实账户读写、在线 Java 安装或原生 aria2 条件门禁。

后续共享夹具修复通过 Headless **364/364**；相对 Java 源码、UTF-8 输出、受控 .NET argv、停止上下文、凭据注入和 RPC 的针对回归 **16/16**。两次构建均为 0 警告、0 错误。证据分别在 `pr15-ci-headless-r2`、`pr15-ci-process-r2` 的注册任务构建目录；没有为了测试调整宿主系统代码页。

显式测试内存补齐后，首页设置、实例展示及截图库三项原失败页面针对回归 **3/3**，构建仍为 0 警告、0 错误；证据在 `pr15-ci-memory-r3`。

Linux 默认生产入口的专属断言在 Windows 条件跳过。首轮修复的 Linux runner 已通过 Core 873 项 / 6 条件跳过，随后 Headless 发现其余三处同类夹具依赖；补齐共享注入，未扩大平台排除或删除这三项测试。macOS/Windows Java 解析、三端桌面测试及打包最终结果以最终修复提交的 Actions 为准；原失败记录继续保留，不将本地 Windows 结果冒称为三端通过。

本地证据位于 `artifacts/windows-main-20261105/build/main/pr15-ci-core-r1/Desktop/Release/win-x64/default/reports`；这些产物不提交，不影响原用户进程、旧工作区改动或凭据数据。

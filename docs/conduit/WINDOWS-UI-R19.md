# R19：数据包与世界存档安装（2026-11-08）

本轮把数据包和世界下载接成可执行的存档安装流程。业务继续在 Core，共用 Avalonia 页面；没有启动 Minecraft、认证账户、切换默认入口、推送或发布。原 WPF 和原工作区修改保留。

## 仍未接齐的功能，优先看这里

1. **存档数据包管理**：更新、删除、排序、更多版本的启停写入和游戏内重载仍未齐（P64）。本轮只安装文件，不改写现有 `level.dat` 的启停状态；既有存档编辑仍限已经验证的版本。文件在磁盘上不等于游戏内已经生效。
2. **特殊数据包/世界**：实验特性声明、需要额外模组/内建数据包的世界、不可核实版本的旧存档、多个世界混装 ZIP、包装目录之外混入文件的 ZIP 目前明确拒绝；不猜版本、忽略依赖或自动升级/降级世界。更多真实组合与用户可解释的处理体验继续补充。
3. **实例与资源管理**：已有实例改组件的完整中后期回滚、更多历史加载器/组合、Java8 自动供给、模组/资源包更新与批量操作、手工文件身份、依赖图、启动脚本导出和多会话明确停止入口仍有缺口。已验证范围见 R17/R18，不能把本轮下载安装算成这些页面全部完成。
4. **其它外壳功能**：个性化完整组合、全局帧率、反馈内置提交/附件、更多日志检索、截图/投影管理和服务器丰富信息仍按 todo 追踪。七语补全、自动更新、视频背景、完整许可清单 UI 已由用户取消，不再列为待开发。
5. **原生验收**：Mac 当前不可用，仍欠本轮 Mac 原生安装/回滚、ARM64 历史库、完整 DPI/跨屏/键盘/无障碍和 SMB/磁盘故障矩阵。跨编译通过不等于双端替代门禁通过。游戏验证仍需当前任务的明确授权，本轮未执行。

## 本轮改动

| 范围 | 行为 |
| --- | --- |
| 数据包详情 | 明确选择登记实例与已有存档；文件旁“预检安装”下载并核验，展示目标和文件数，单独“确认安装”才写入。改变目标或资源项目使旧确认失效 |
| 世界详情 | 明确选择实例及新的存档文件夹，不覆盖同名世界；唯一 Java 世界可在 ZIP 根目录或包装目录内 |
| 兼容性 | 复用官方大小/SHA-1 校验与版本解析，从基础客户端 `version.json` 取得实际 DataVersion、数据包格式及小版本；对照目标 NBT 与发布资源标签，不推断跨版本兼容 |
| 数据包依赖 | 必需依赖按精确版本或项目解析，限制层数/数量/总量；双用途 Modrinth 项目必须选择 datapack 分支。详情查询不误用 Forge 等 Mod loader，JAR 不提供存档预检按钮 |
| 冲突 | 检查已有项目/文件版本、大小写与 Unicode 重名、格式范围、实际生效 overlay、资源重定义及标签合并；可合并标签保留游戏语义，不覆盖其它文件。内带数据包的世界也先检查 |
| 回滚 | 数据包暂存完成后再发布文件、最后提交清单；晚期失败只回收本次新增且哈希仍匹配的文件及空目录。世界在自有暂存完整核验后原子发布，取消/失败不登记半成品 |
| 目标复核 | 确认时重查实例身份、运行状态、物理目录/文件身份、存档与既有包指纹，以及缓存档案 SHA-256；预检最长 30 分钟、最多保留 8 项 |
| 页面状态 | 正常操作不添加底部 loading 长条，复用已有镐子操作/取消界面和任务传输状态。修复跨项目残留成功提示，失败不显示成功或留下可用的旧确认 |

新增接口为 `IWorldContentInstallationService`，实现集中在 `LauncherService.WorldContent.cs` 和 `Content/WorldContentArchive.cs`；复用 `ContentInstallPlanner`、`ContentInstallFiles`、`PackArchiveReader`、`InstanceWorldStore`、`VerifiedDownloader` 与原子发布。平台差异继续经已有路径/文件身份适配层处理，没有 Windows 产品路径硬编码或 WPF fallback。

存档选项不静默选择第一个世界，也不更换首页的当前实例。世界安装只创建新目录；数据包只装入明确选中的世界，不写原实例 JSON、未知配置字段或账户数据。下载缓存沿用受控、可复用的缓存/续传机制；“暂存为零”指目标存档的安装暂存，不宣称所有缓存续传片段都会删除。

## 实际文件与原生窗口证据

**数据包**：真实 Modrinth 项目 `OhduvhIc`，版本 `8cEJouzY`，文件 `Veinminer-1.2.4.zip`，目标为 Java 1.21.1 的自建存档“明确目标 中文 空格”。下载/预检时目标无变化，确认新增 1 个文件，`level.dat` 字节不变；重复安装新增 0。ZIP SHA-1 为 `e6ebe9ce76023bdb79e55d20a40336db93855d0b`。

**世界**：真实 CurseForge 项目 `563455`、文件 `3590460`，ZIP 内版本 Java 1.18.1。先安装到“下载世界 中文”，43 个归档文件逐项核对 SHA-256，NBT 不变、旧 `session.lock` 不导入、另存公开来源收据。搜索中有三份其它项目文件的标签与 ZIP 内实际版本不一致，验收拒绝它们，没有放宽身份检查。

**Windows 原生 RC2**：200% DPI、1952×1272 像素窗口，零账户隔离目录。使用两条公开资源 ID 的本地收藏夹具进入详情，真实 API 读取文件；实际鼠标选择实例/中文存档、预检、取消预检、再次确认，数据包重复复用新增 0。世界页面另行预检/确认安装到 `r19-world`，新增 43 个文件。文件夹输入框的编辑状态留图，完整绑定由 Desktop 控件测试覆盖。

**Windows 原生 RC3**：同一隔离数据目录重启可读；已有 `r19-world` 目标被明确拒绝。转到数据包详情时项目状态清空，修复前的跨项目残留未再出现；实际鼠标关闭 exit0。RC2 后期置前台受限，改用精确核对自有进程后的正常关闭消息，也为 exit0。两轮均无外层超时。

关闭并重启后，再核对两个世界各 43 个原始文件、数据包 SHA-1、外来冲突文件均保持，目标安装暂存为 0。原生截图仅含本轮零账户、自建目标及公开资源。Computer Use 截图两次超时后按既有授权使用备用截图/原生输入，曾遇前台限制并停止输入，恢复后继续；没有操作登录或安全授权界面。

**真实中断**：在真实 CF 世界安装的 `.shou-world-install-*` 目录已创建后，以文件系统通知触发取消，结果为 TaskCanceledException，暂存清理且无目标；另一次在中途创建同名外来目录，结果 IOException，外来 `external.txt` 保留，未落入 `level.dat`。均非仅在入口预取消。受控 Core 另覆盖数据包文件已发布后的失败/取消及世界后续条目 CRC 错误回滚。

这些验收只读/写安装文件，不调用游戏入口。服务验收的 `IProcessRunner` 对 Run/Start 均明确拒绝，三阶段 `gameProcessCalls` 全部为 0。游戏内启用、资源效果或世界渲染没有验证。

## 回归与首次失败

- **Core：515 通过 / 16 显式跳过 / 0 失败，总计 531**。比 R18 增加 41 项，覆盖实际 NBT/ZIP 文件、现代/旧格式、依赖、路径/资源/文件冲突、缓存或目标变化、取消及晚期回滚。最后一次 Core 变更对应 `d3926923`；后续仅改页面状态及其 Desktop 断言。
- **Desktop：180 通过 / 0 跳过 / 0 失败**。实际 Avalonia 控件覆盖实例/世界选择、新文件夹名、独立确认、目标变更、预检取消、失败反馈、项目切换、datapack 查询分支与 ZIP/JAR 按钮守卫；最后一次状态修复后完整复跑通过。
- 16 项跳过沿用显式平台/独立门禁：4 项 Mac 原生/Keychain/argv、8 项 Windows 独立链接/重解析夹具、1 项 POSIX 失败子进程、1 项未启用在线 Java、2 项未启用受控 Java 修复副本。逐项名称及原因存于 `r19-acceptance-summary.json`，没有把跳过记为通过。

| 首次发现 | 处理与证据 |
| --- | --- |
| Core 初跑 27 失败，随后 2 失败 | 新夹具没有覆盖已配置的镜像路径；CRC 夹具误改文件名而非 CRC，失败注入也漏了镜像。补精确路径与真实 CRC/中断注入，保留断言和首次 TRX，最终 515/16 |
| 实际 Modrinth 数据包身份与预想不同 | v2 双用途项目返回 mod，所选发行有 datapack loader；仅在明确存档作用域内核实并适配，不全局重分类或安装 Mod JAR |
| 世界内合法 token 游戏资源被过严名称检查误拦 | 改为根级明确账户/凭据名和程序扩展名限制，保留路径/链接/数量/体积守卫，增加真实目录数据包资源回归 |
| 原生跨项目提示残留 | 项目改变时清除对应状态；Desktop 跨项目成功提示断言及 RC3 原生冲突后切页复验通过 |
| 本机验收 harness 首次编译 CS4007；XAML Watermark 过时警告 | 前者为 await 跨 Span 的控制程序写法，改为先 await 字节；后者改用 PlaceholderText，最终构建 0 警告/0 错误 |

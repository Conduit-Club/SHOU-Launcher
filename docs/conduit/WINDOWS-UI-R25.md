## 本轮行为

数据包页接入“更新备份”入口，列表区分可检查、已恢复、后续状态改变、不完整、旧格式与损坏记录。可先打开备份目录人工核对；恢复必须先检查，再明确确认。选中备份或实例/存档变化、取消及迟到响应会使预检失效；有未保存的顺序草稿不能恢复，预检也会失效。沿用共享 Core、ViewModel、字体与按钮；页内 LoadingGlyph/状态，不新增底部进度条。

新更新收据保存原包类型/哈希、更新前后 level.dat/清单快照、完整数据包修订和创建时间。兼容范围仍为 R24 已验证的 Java 1.21.1 / 3955 / 格式 48.0 与 26.2 / 4903 / 格式 107.1，不扩大 R22 世界元数据/启停/回收写入范围。

恢复预检与确认都核对当前 level.dat、全部数据包和来源清单仍等于该次更新后的完整修订，同时核对原备份、版本与路径/名称；有后续排序、修改或新文件便拒绝覆盖。恢复复制原备份，不消耗原件；替换版本及其元数据移入同条备份的 restore-current 独立目录，保留更新前后两份资料。新增依赖随该次更新一同移回备份，不删除其它项目。多次更新须从最新状态逆序恢复。

文件及目录均使用物理路径和节点守卫，单条记录最多 64 个文件，恢复原包总预算 256 MiB，沿用单文件/深度/节点预算。未知 NBT/来源字段随原始快照逐字节恢复。准备阶段不改当前包；发布和元数据写入失败或取消时恢复本次操作前状态，并清理本次暂存。出现外来竞争、备份损坏或无法安全回滚时保留恢复资料、明确报错，不覆盖外来文件。完成标记是提交点，提交完成后到达的取消不宣称回滚。

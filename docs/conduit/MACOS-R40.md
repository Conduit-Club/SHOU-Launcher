# R40：递归模组声明与关系页（2026-11-12）

本轮承接 R39 的模组管理，对照旧 WPF 的 `ModJarInJar`、`ModJarInJarIndex` 与 `PageInstanceCompJarInJar`，在独立 Core/Avalonia 中补齐只读声明分析。旧 WPF 源码、游戏启动参数、平台兼容补丁、个人应用和实例均未改动。

## 本轮实现

- 独立的 `IInstanceModRelationsService`：进入关系页才读取递归声明，搜索和筛选使用已读取结果，不增加模组列表首屏的递归工作；不请求在线目录，不提取或执行 JAR 内容。
- 读取 Fabric/Quilt 的 ID、别名、必需/可选依赖及原始版本要求，递归声明中的 JAR；读取 Forge/NeoForge 多 Mod ID、依赖和 JarJar 清单，以及 `mcmod.info` 中的多个 ID/必需依赖。多加载器 JAR 优先使用当前实例加载器的声明；NeoForge 的冲突声明不误列成依赖。
- 依赖来源区分独立声明、内嵌声明、仅存在于已禁用文件、未找到声明、读取不完整。内嵌节点继承物理宿主的启用状态；损坏子归档保留父节点，未核实项不当作兼容或最新版。
- 新的“模组关系”页提供文件选择、深层 ID/依赖搜索、“只看需要检查的文件”、依赖来源路径、缩进的递归声明树、错误详情、重新读取与返回模组。“检查模组”入口接入此页；不支持新接口的测试/旧服务保留原基础诊断。
- 读取有独立取消和代际检查：离页、切换实例、关闭界面丢弃迟到结果。模组写操作等待已取消的关系读取释放文件句柄，继续保留 Windows 的读写顺序。
- 新增界面静态文案维护简体中文、繁體中文和 English。

分析边界沿旧 WPF 读取器的五层嵌入、每宿主 512 节点、单内嵌项 256 MiB、每宿主 512 MiB、整次读取 2 GiB；超出时明确展示不完整。它们只约束这次只读分析，不限制导入、删改、游戏加载，也不会过滤整合包内容。源码读取还核对大小/修改时间和取消，不把被修改的文件继续作为完整结果。

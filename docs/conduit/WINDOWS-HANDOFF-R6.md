# Windows 接手开发 Prompt

请接手潮涌核心社启动器的 Windows 主开发工作。目标是沿用现有 Avalonia 跨平台实现，继续复刻旧 WPF 的可观察 UI 和有效功能，最终达到替换旧版的条件。不要另做一套 Windows 专用启动器，也不要把已验证的 Mac 能力丢掉。

## 0. 接手分支与边界

仓库为 https://github.com/Conduit-Club/SHOU-Launcher，接手分支为 origin/features/wpf-parity。先读 AGENTS.md、CONTRIBUTING.md、docs/conduit/WPF-PARITY.md、WPF-PARITY-R5.md、WPF-PARITY-R6.md 及 MACOS-MIGRATION.md，检查 Git 状态、origin 实际地址和分支关系。

这次是在既有迁移分支上续作。产品最后检查点为 69fe954，另有交接文档提交；先取得远端该分支最新头，不要退回旧候选源码，也不要擅自把 main/dev 合进来。保留 Windows 原工作区的已有修改，优先新建独立工作树。若分支已存在或远端分叉，先分析并报告，禁止 reset --hard、强推或覆盖当前工作。

允许按功能做本地分阶段提交。后续推送、PR、合并、Windows 默认入口切换和正式发布，按我在本会话的明确授权执行；Mac 这一轮的推送授权不扩展成无限发布权限。每个阶段说明改动、验证与剩余项。

当前核心为 .NET SDK 10.0.403、Avalonia 12.1.5，遵循仓库锁定版本及构建入口。Laptop 曾只有运行时而没有 SDK，先核实本机状态，再在项目隔离工具目录恢复必要工具。不要盲用 Mac 的绝对路径或污染全局环境。

## 1. 先短预检，再开始开发

先确认依赖能恢复、win-x64 自包含候选能打开、磁盘预算/取消/超时和日志脱敏有效，旧 WPF 与新 UI 都能独立运行。提前处理必须由我交互的登录/系统授权步骤；等待授权、进程存活、Headless 成功均不能算实窗验收通过。

本地样本和既有 Windows 报告可能位于 D:\Code\C#\PCL-CE-SHOU\artifacts\mac-validation-r6，按实际路径核实。跨机器传候选和非敏感证据优先 SMB，复制前后核对 SHA-256；Git 传源码，SMB 传候选/测试素材/报告。

不要在工作目录执行整个旧解决方案加 RID 的试探构建。使用仓库的 Desktop/Core 项目及 Publish-Desktop.ps1、Validate-Desktop.ps1，先读脚本参数；重任务串行，保存首次失败、命令、源码 SHA、SDK/RID、TRX 和最终结果。

## 2. 以旧 WPF 实窗为参照校对 UI

保持 cleanroom：可以运行旧 WPF、点击观察、并排截图、记录尺寸和交互；实现只用净化后的正式 PNG、可观察说明、新 SHOU 代码和可移植业务接口。不要读取或复制旧 WPF 视图、样式模板、结构映射 JSON 或采集脚本作为实现输入。git diff 用来检查新实现和本轮变化。

先制作逐页差异清单，按“视觉差异、交互缺失、业务未完成、计划移除”登记，然后按用户影响排序处理。不要只处理首页，也不要把旧版无效功能照搬成占位按钮。

优先修复：
- Windows 右上角缺少最大化/还原按钮。补齐最小化、最大化/还原、关闭及可访问名称；验证标题栏拖动、双击、系统贴靠、快捷键、最大化后的工作区和恢复尺寸。
- 图标大小、ViewBox、笔画、按钮内边距、文字与图标基线、菜单/输入框行高、复选框、下拉箭头及状态图标的一致性。
- 检查 Windows 实际字体及中文回退，统一字号/字重/行高，避免中文和拉丁字体造成错位；不要依赖 Mac 字体，也不要未经许可打包字体。
- 核对 100%、125%、150%、200% DPI、跨显示器移动、880×560 最小窗及常用尺寸，检查文字裁切、滚动、弹层定位、焦点、Tab/Enter/Esc 和高对比/浅深主题。
- 保留平台差异：Mac 原生三钮在左，Logo/标题靠右；Windows 标准窗口按钮在右。平台差异留在窗口适配层，共享页面继续共用实现。
- 补验新配置首页默认显示社团介绍与服务器卡片；已保存隐藏偏好仍须保留。Mac 最后发现并提交了这项修复，尚未构建新的原生候选。

## 3. 移除启动器联机模块

本轮移除范围为启动器的联机大厅、房间/P2P/EasyTier/穿透及其专属入口、设置和无用依赖；Minecraft 原生多人游戏、服务器列表/地址、社团服务器信息、正版认证、下载网络和 HTTP 代理继续保留。

先列出新版中的联机 UI、命令、服务、配置和依赖引用，确认边界后清理；不要只藏按钮却留下失效导航。旧配置里的未知/历史字段要兼容保留，避免旧→新→旧往返时丢数据。不要为了这项清理改写或删除用户原数据、旧 WPF 参考工程。

## 4. 将 Java 证书修复增加到工具页

现有 Core 已有 Java 信任检查和创建独立修复副本能力，设置页也有入口。本轮把手动诊断/修复整理为工具页中明确、易理解的入口，复用原服务与状态管理；Java 设置页保留自动修复偏好或跳转入口，避免维护两套逻辑。

流程应能选择明确的 Java 路径、只读扫描、区分健康/需修复/未知结果、显示可执行修复、创建并核验独立副本、明确选用与回退。保留原 Java、备份/收据/来源记录和其它证书；失败或取消不得选用不完整副本。不要关闭 TLS 验证、信任所有证书或直接修改系统/原 JDK 信任库。

在 Windows 上用真实 Java 和受控损坏副本验证，并核对原始 Java 哈希不变、修复后能探测/启动，重复执行能安全复用。常规检测不应无故触发管理员权限。

## 5. 完成有效功能并验证真实正版登录

逐页核对“能看到、能操作、真正执行、写盘后重启仍有效”，特别关注账号添加/切换/刷新/移除、Java 自动/手动选择、实例隔离和设置优先级、下载与加载器、整合包、模组/资源包、存档/截图/服务器以及取消/重试/错误反馈。

可以使用我这台 Windows 上、我提供或明确用于本项目的旧启动器数据目录中的正版账户缓存进行登录兼容测试。优先沿用应用支持的读取/迁移路径、Windows 当前用户的 DPAPI/凭据服务。限定于本项目和当前用户，保留原目录和原文件；无法正常读取时按标准 OAuth 授权登录。

禁止把密码、Cookie、access/refresh token、会话密钥、完整账户缓存写入聊天、终端输出、截图、测试夹具、Git、SMB、候选包或报告。不要扫描无关浏览器或其它账号存储。报告只记录脱敏结果、错误类别和是否成功。

真正验证账户刷新、Minecraft profile/所有权、一次正版游戏启动到主菜单和正常 Quit；沿用现有安全凭据传递，不把 token 放到可见命令行。旧账户读取成功、离线角色成功或生成启动计划均不能代替正版登录成功。需要我交互时清楚指出步骤，继续其它不依赖它的工作。

## 6. 保住已有跨平台能力

已有 R6 RC3 在 Mac/Windows 均能运行。Mac 的 FO 6.5 ZIP 与 MRpack 均已真实拖入、安装 113 文件/48 Mod JAR/3 资源 ZIP，并完成 Minecraft 1.21.1、Fabric 0.19.3 主菜单、Mod Menu、隔离单人世界渲染保存与正常 Quit exit0。Windows 已实际导入 MRpack、CF 6.5 和 CF 6.4，逐文件核验，并完成启动器原生导航/最小窗/最小化恢复/正常关闭；Windows 游戏及真实正版认证尚未测。

保留：
- ZIP/MRpack 真实系统拖入、预检后显式确认、独立新实例、失败/取消回滚。
- 精确清单身份、类别/路径、哈希与大小校验，无下载 sidecar 混入实例。
- 官方 CDN 逐跳白名单、API 凭据隔离；CF 无下载地址时仅用独立发布的精确哈希匹配文件。

- 导入后的首次一键准备与启动，失败/取消不启动。
- Windows DPAPI、Mac Keychain、数据根互斥、配置未知字段、写前备份与安全回退。

共享业务放在 Core，平台行为经适配层实现；禁止在业务里堆 Windows 绝对路径或用 WPF fallback 掩盖新 UI 缺失。为 Mac 构建候选并通过 SMB 交回原生验收；Mac 暂时不可用就明确列为待验，不把交叉构建等同于真实运行。

## 4. 高优先级：启动状态与游戏生命周期

### 4.1 已确认的当前实现

- [MainWindow.axaml](../../src/SHOU.Launcher.Desktop/Views/MainWindow.axaml) 的 OperationBar 位于全局底部；Running 时显示停止游戏按钮和 StateSummary。
- [MainWindowViewModel.cs](../../src/SHOU.Launcher.Desktop/ViewModels/MainWindowViewModel.cs) 的 StateSummary 拼入 PID；ShowOperationStatus 在 IsBusy 或 HasRunningGame 时为真。CanMutate 仅允许 Ready/Error，所以游戏运行会影响账户、实例及设置操作，不只是按钮外观。
- [LauncherService.cs](../../src/SHOU.Launcher.Core/LauncherService.cs) 仅维护一个 game / gameObserver / GameProcessId；LaunchAsync 在现有游戏未退出时拒绝再次启动。
- 游戏 StartAsync 使用 LauncherService 的 lifetime.Token。DisposeAsync 取消 lifetime 并调用 current.StopAsync。
- [Bootstrap.Hosting.cs](../../src/SHOU.Launcher.Desktop/Bootstrap.Hosting.cs) 在退出时执行 ShutdownHostAsync，释放 Launcher 和 Processes；[ProcessRunner.cs](../../src/SHOU.Launcher.Desktop/Platform/ProcessRunner.cs) 对所拥有进程的 Dispose/Stop 也有终止路径。

因此“关启动器会杀游戏”是当前源码中的实际风险，不是只需改一条文案的误会。此前 R7 验收是游戏内 Quit exit0，然后关闭启动器；没有证明游戏运行时关启动器能独立存活。本次不通过实启/杀进程再现来改动用户会话。

### 4.2 下一轮目标状态序列

正常账户/头像区 → 左侧准备状态 → 登录/下载/校验状态 → 创建游戏进程 → 等待游戏窗口 → 恢复正常账户/头像区。

- 左侧保留当前步骤、真实可用的阶段进度、实例名省略/完整提示、明确取消；错误/取消回到可重试状态并保留选择。
- 创建 PID 不代表窗口出现或主菜单完成；不能把启动次数、PID 或启动计划当作视觉成功。
- 正常首页不常驻 PID 长条；会话技术信息可放实例详情/日志。其它页面的真实后台下载可保留适当任务入口，不要求把所有任务反馈都塞到左栏。
- “取消准备”“停止指定游戏”“关闭启动器”必须是三种不同动作。游戏已成功启动后，不可因关窗口或 UI 释放触发停止游戏。
- 允许不同实例并行；同一实例写盘冲突应给出准确限制，而不是全启动器 Running 全局禁用。

### 4.3 不是简单删掉 StopAsync

需要将 UI 生命周期、准备任务取消和已启动游戏会话所有权分开。保持安全 stdin 引导、启动前失败清理和取消不继续启动；解决 stdout/stderr 关闭、日志持续写入、退出观察、重启识别与进程句柄释放。若采用受控辅助进程/会话注册表，平台差异放在适配层，共享策略放 Core。

实例写入锁也要随游戏会话有效：启动器关闭后释放全局数据根锁，不等于可以允许另一个启动器编辑仍在运行的实例。识别会话不能仅凭 PID，需防止 PID 复用、错认/终止其它 Java 进程；不得将令牌写到命令行、会话登记、日志或可共享目录。

验收必须包含：运行中正常关闭启动器后游戏仍活着、重开能正确识别；不同实例 A/B 并开；同实例冲突；取消/失败只回滚本次准备；游戏崩溃不锁死 UI；两个游戏分别 Quit；只停止用户明确选中的会话。Windows 与 macOS 都要原生验证。

## 5. 图标、字体与版式的可复用边界

### 5.1 可以复用什么

本地独立素材目录 [PCL.Core/UI/Assets/IconPacks/lucide](../../PCL.Core/UI/Assets/IconPacks/lucide/) 现有 87 个 SVG。文件注释标识 lucide-static v1.17.0；检查的 play/puzzle 等文件使用 24×24 ViewBox、currentColor 描边及统一线条属性。随目录的 [LICENSE.txt](../../PCL.Core/UI/Assets/IconPacks/lucide/LICENSE.txt) 为 ISC，并对列明的 Feather 派生图标附 MIT 条款和版权声明。

**结论：具备复用这些独立 SVG 到双端图标组件的可行基础。** 下轮应逐项记录所用文件、来源/版本/哈希与随包许可，保留对应版权及许可文本。只复用资产，不把 WPF ResourceDictionary、控件模板、转换器或控件树作为跨平台实现输入，也不因复用图标引入 WPF 运行时依赖。本次不复制进产品资产目录、不改图标组件。

旧工程另有 Font.ttf，仅发现文件不代表已经核实来源和再分发许可；不顺带打包该字体。版本方块图、Logo 等非 Lucide 素材分别核对来源，不能将图标包许可扩张到全部旧资源。

### 5.2 当前差异和下一轮组件规则

- 新版 [ClubIcons.cs](../../src/SHOU.Launcher.Desktop/Themes/ClubIcons.cs) 是自绘路径集合，顶栏还含独立内联 Path；并非直接使用上述完整 SVG 组件。
- [DownloadsView.axaml](../../src/SHOU.Launcher.Desktop/Views/DownloadsView.axaml) 的侧栏是 22 DIP 图标列配 18 DIP 图形，文字没有独立间距列；需连同描边/图形留白检查，不能只看控件 Width。
- 新版 Minecraft 与整合包若共用立方体路径，会削弱旧版两种语义的区分；下轮按语义选图，不能只改颜色。
- 共享组件应统一 ViewBox、外框尺寸、笔画、圆端/圆角、缩放方式、主题色、图文间距、垂直中心和命中区域；图标不独立抢 Tab 焦点，按钮仍有完整可访问名称。
- Windows 实际字体与中文回退、macOS 实际字体与中文回退分别测量；共享字号/字重/行高规范，不以 Mac 字体是否存在决定 Windows 排版。当前 ClubStyles 的系统字体列表不等于已经逐字验证实际 fallback。
- 检查 SHOU 徽标、标题导航、侧栏、按钮、TextBox、ComboBox、NumericUpDown、CheckBox、菜单/提示、长路径、省略和滚动。图 1/2 的主题差异须先对齐设置，不把用户配色覆盖成固定色。

### 跨页还需单列的缺口

- 首页服务器卡当前自动入服会在 Core 被 serverId 非 none 条件拒绝，实例 LaunchCommand 也限制选择“只启动游戏”。这是保留功能范围内的未完成项，不是移除联机大厅的理由。提示中“真实账户门禁尚未通过”也已落后于 R7 实测，后续须区分登录已通过与入服未通过。
- 运行生命周期之外，全局状态过度绑定 CanMutate，影响设置/账户/其它实例操作；不能只把底栏隐藏后声称恢复并行能力。
- 技术性/重复文案、灰态占位、菜单项无行为、错误恢复与空态需要逐页按“可见→可操作→真实执行→重启保持”复核；已有文案精简不代表全页已经干净。
- 未知配置字段、写前备份、损坏配置禁写、旧→新→旧往返、同根双入口互斥仍是正式替代门禁。关闭启动器后保留游戏会新增跨进程实例锁要求。

## 界面与共享行为

数据包页选中一个包后可检查更新。有精确安装来源且大小、SHA-1 和 SHA-512 全匹配时，通过原提供方读取适配世界版本的其它发布文件；明确选择版本和文件，先检查兼容性、依赖与冲突，再确认更新。网络读取失败不假称没有更新，仍可重试或选择本地 ZIP。文件夹、未登记或修改后的包提供本地替换；手动替换不伪造在线身份，原记录留在备份。

更新沿用 Core 提供方与下载校验。必需依赖按项目/版本精确解析，拒绝非数据包依赖、固定版本矛盾、循环和不兼容声明，并核对未更新的登记包，防止更新破坏其它包的必需依赖。保留原根包启停状态；仅根包启用时将缺失的必需依赖加入 Enabled，放在根包前。用户明确禁用的依赖不被自动启用。旧依赖不会擅自删除。

加载顺序写入真正的 `level.dat → DataPacks.Enabled`。界面从低到高排列，后项优先；此语义对应官方 [`/datapack enable … last` 的优先级说明](https://www.minecraft.net/en-us/article/minecraft-snapshot-17w46a)。内建/未知 ID 保留原位置，Disabled 列表不变；只允许重排全部已启用的本地文件包，已有资源重叠会提示覆盖结果可能改变，不把排序当作启停或静默覆盖文件。

上下移动仅改草稿，明确保存才写盘。未保存的顺序草稿阻止其它数据包写操作；放弃后恢复按钮状态。版本、选包或目标改变会使预检失效并释放旧计划，迟到响应不填入新目标。文件选择器返回时再核对捕获的实例/存档/包。耗时检查采用页内 LoadingGlyph 与取消，不新增底部进度条。Windows/macOS 使用同一 Core、ViewModel 和 Avalonia 页面，仅文件选择器走平台接口。

## 兼容、备份与事务

更新/排序目前仅写入已核实的 Java **1.21.1 / DataVersion 3955 / 格式 48.0** 和 **26.2 / DataVersion 4903 / 格式 107.1**。更新还核对目标实例与官方客户端 version.json 的实际世界格式；此过程只读校验文件，不执行游戏。存档、所有包及来源清单共同组成预检修订，确认时重查，拒绝过期目标、改动后的缓存/ZIP、大小写/Unicode 重名、路径/链接及资源冲突。

更新最多 64 个项目/文件，单 ZIP 64 MiB、本次 ZIP 总计 128 MiB，已有包与展开资源总计有 256 MiB 预算；目录深度 24、5000 节点等守卫沿用。更新在存档独立暂存目录准备，旧包移至 `.shou-backups/datapack-updates/<id>/payload`；同时保存原 `level.dat`、来源清单和收据，再发布校验后的新包、迁移改名引用、写元数据并标记完成。来源清单和 NBT 未知字段保留，源 ZIP 不修改；每次精确备份，最多 256 组，达到预算后要求先自行备份整理，不自动删除。

正常取消或失败会回滚本次已替换的文件和元数据，清理本次暂存。目标出现外来修改时拒绝覆盖，保留恢复资料并报错；不假称这种外部竞争或断电情况一定可自动修复。排序独立使用元数据原子写入和写前备份，核对成员/内容及世界修订；坏包或不明确列表不猜测。

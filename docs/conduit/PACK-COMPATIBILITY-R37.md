# R37：撤销整合包内容过滤与移植限制审计

本轮按用户要求，撤销移植时额外添加的目录/扩展名白名单，恢复旧 WPF v1.5.0 的客户端覆盖内容复制语义。旧版参考为 `8746ad26f9df1eff9f5a3ea57311f82a14ec181b`，以本仓库历史文件核对，不追踪原上游。

## 修正

| 项目 | 旧版调用链/行为 | 此前移植差异 | 本轮处理 |
|---|---|---|---|
| CF overrides | `ModModpack.CopyOverrideDirectory → ModBase.CopyDirectory → EnumerateFiles("*", AllDirectories)` | 名单外目录/脚本/原生库/存档直接跳过 | 全量复制指定覆盖内容，`SkippedFiles` 不再因自设类型过滤增加 |
| MRpack 客户端内容 | 下载清单 + overrides + client-overrides | 仅接受七种目录与三个根文件 | 合法路径均可导入，客户端覆盖层优先 |
| 脚本与原生库 | 覆盖目录中原样复制 | `.sh/.dll/.so/.js` 等额外过滤 | 按字节保存；导入/导出程序不调用它们。游戏加载模组脚本的行为保持 |
| MRpack 下载来源 | 读取包内 downloads，再应用下载源设置 | 强制单一 CDN、默认端口、最多八个来源 | 读取包内 HTTP(S) 来源，保留既有 HTTPS 用户设置、大小/SHA-1/SHA-512 与无 URL 账号密码要求；有实际 VerifiedDownloader 夹具 |
| MRpack 附加文档 | 解压后只复制格式声明的覆盖层 | README/额外目录使整包拒绝 | 附加文档可共存，只从客户端层取游戏内容；路径/归档检查仍覆盖 ZIP |
| 包裹目录 | 旧入口能识别一层包目录 | CF/MRpack 只接受根标识 | 支持一层包裹目录，多个有效候选仍明确报错 |
| CF 根覆盖 | 旧版处理 `.` / `./` | 作为非法相对路径拒绝 | 恢复根覆盖及尾斜杠写法；原 manifest 作为覆盖内容保留 |
| CF 文件数 | 原列表未设 512 项产品上限 | 硬上限 512 | 与现有整体 8,192 文件预算统一；600 项清单/解析回归通过，解析总时限随工作量调整 |
| CF 世界 ZIP | `level.dat` 类型路由到 saves | 世界类被拒绝 | 恢复官方 world 类到 saves 的 ZIP 路由；未宣称已自动解压/可进入世界 |
| MRpack/CF 导出 | 旧导出可选择其它目录 | 导出沿用目录/扩展限制 | 选择或安装清单中的合法内容可往返 |
| SHOU 导出/导入 | 新格式，无同名旧格式 | `account/token/password` 关键词、点文件、扩展名及 2,048 项过滤 | 去除关键词/扩展/隐藏文件误判；默认导出增加已导入清单的目录和根文件；数量使用共同预算 |
| 首次在线查询 | 旧页保留搜索和本地入口 | 无结果时全页加载遮挡入口 | 查询徽标/取消保留，本地预检不必等待网络；最小窗口有延迟请求回归 |
| 根覆盖再导出 | 完整内容可保留原 manifest | SHOU 再导入将原 manifest 误判为第二格式 | 精确 SHOU 清单明确列出的其它标识视为数据并继续逐文件验哈希；自身元数据名冲突明确报错，可换 MRpack/CF 格式 |

凭据的导入与保存内容是两条路径：导入覆盖目录中的同名 JSON 仅保存为实例文件，不读取成启动器账户。导出仍排除已知**根目录**凭据文件 `launcher_accounts.json`、`launcher_accounts_microsoft_store.json`、`shou.desktop.v1.json`、`credentials.json`、`accounts.json`、`authentication.json` 和 `.env`；`config/account-token-addon.json` 等普通模组配置不再按名字猜测并丢弃。旧导出也有独立的启动器配置选项，不能将隐私排除混同为游戏数据目录白名单。

保留路径越界、链接/重解析点、大小写/Unicode 冲突、CRC、下载哈希、原归档变化、事务失败回滚及生成清单名冲突检查。工作副本改放在暂存目录旁，避免与同名合法包文件互相覆盖。这些检查失败会明确拒绝本次导入，不删掉一部分文件再冒称成功。

## 其它审计发现与待办

本轮静态扫描命中 39 个文件、137 处限制/能力提示，再追上述旧版调用链及设置、工具的相关条件。这是一次定点审计，尚未完成整个旧 WPF 的逐功能审计。

- **CF 可选文件选择缺失（P1）**：旧版逐项询问 `required=false` 是否下载，新 resolver 仅解析 required，尚无对应选择 UI。应显示可选项并尊重选择，不能直接改成全部安装或继续静默略过。
- **归档工程边界（P1）**：仍有 ZIP 256 MiB、展开 512 MiB、单文件 128 MiB、整体 8,192 文件/10,000 ZIP 条目、下载合计 4 GiB、安装清单 4 MiB，以及 ZIP64/多卷不支持。这些是移植边界，不是已核实的旧版产品限制。后续须以流式读写、磁盘余量和可取消检查替代过小固定边界，不能只调大内存上限或去掉完整性检查。
- **更多格式/加载器（P1）**：旧版还有 HMCL、MCBBS、MultiMC 和普通压缩实例等入口；当前 MultiMC 仅预检、其它格式未完整接入，多个加载器组合也受限。属于尚未完成的移植，不能显示成旧版原有禁止项。
- **远程 aria2（P2）**：用户要求默认 localhost:6800 与端口优先，并未要求禁止远程端点。当前仅本机校验是额外的实现边界；远程普通文件与 CF 本机中继如何衔接仍需完成，未擅自暴露中继监听地址。
- **额外勾选门槛（P2）**：更新单个模组、修改加载器采用确认勾选后再按按钮；旧版有确认提示，但交互形态不同。应另行核对并简化重复确认，文件替换/删除的恢复保护继续保留。
- **目录与下载差距**：实例目录命名/迁移、内置自适应分段、逐文件暂停、跨重启历史等沿用 R30/R33 待办，不能据已有设置或按钮称为完成。

联机大厅、视频背景、启动器自动更新以及额外语言，均有用户明确缩减范围的记录，本轮保留相应决定。系统/运行时架构校验及运行中实例写保护属于可核实的执行条件，未一并撤掉。

## 实现与兼容范围

共享 `Core` 增加独立初始内存、Classpath 头部 JAR、Windows 控制台 Java 选择、调试级 log4j 配置；既有 JVM/游戏参数、窗口、IP、优先级和前置程序通过实例页编辑。前置程序使用明确可执行路径和独立参数，不自动执行旧 Shell 命令。Classpath 每行一个绝对本机 JAR 路径、最多 16 项，检查路径链接、存在性、大小和 ZIP 结构，按给定顺序放在游戏库前；保留受保护的认证传递和启动引导。

JVM 文本兼容空格或换行分隔的受支持参数；不接受用户参数覆盖认证、证书、引导代理或游戏主入口。Windows 的 `java.exe`/`javaw.exe` 差异只在计划适配层选择同目录可执行文件；Mac 不显示这一专属复选框。调试配置由共享服务生成固定内容，不导入来源不明的 XML。全局设置的其它编辑保留新增字段，不丢实例独立值。

目录覆盖有“保持当前”“跟随全局”“独立”“共用”四种。旧实例的两个锚点来自已确认的版本目录和 Minecraft 根；受管实例保留原有隔离目录及对应 `shared-game`。显示目标路径，实际改变目录须再次确认。设置保存只改变引用，不创建、搬移、合并或删除游戏内容；显式点击文件夹按钮才允许创建新的空目标。保持当前是兼容默认，不把已接入实例悄悄搬到新位置。

跟随全局的实例在全局隔离或加载器改变时重新计算路径；任何目标冲突会拒绝同一设置事务。当前和目标游戏会话、路径链接、文件占位、已登记的不兼容版本/加载器模组混用均有守卫。**该检查不能诊断任意未登记共享目录中所有手工模组的兼容性**；切换前仍须核对目标，不以目录可访问宣称模组可运行。

只读“读取此实例的旧版设置”入口位于有旧来源的实例设置页。白名单读取所选 `PCL/Setup.ini`，兼容 UTF-8/UTF-16LE，限 256 KiB；显式 V2/V1 隔离覆盖原有加载器推断。支持的非空标题、自定义信息、JVM/游戏参数、Classpath 及调试设置先成为草稿，须核对后保存。未知或不支持值留在原文件；提示不回显原始命令/敏感参数。旧前置命令、Java 格式和内存刻度不猜测转换。原 JSON/INI/图标不写回，旧→新→旧仍能使用原资料。

配置和目录策略共同持久化，沿用写前 `.bak`、未知根/实例/启动选项/目录字段合并。新侧高级设置不会写入旧 WPF INI，因此这里的往返是**原文件不损失、原旧版仍可读取**，并非两套程序双向同步新增设置。

## 脚本导出

实例概览接入 Windows `.cmd` / macOS `.command` 原生另存。文件只引用当前启动器、必要时的独立数据根和已保存实例 ID；账户刷新、所有权检查、依赖准备和安全凭据传递继续走现有服务。没有选中账户时返回明确失败，不创建离线角色兜底。未保存的草稿不能直接导出。

脚本不包含账户缓存、access/refresh token、Java argv、前置命令、用户名或密码。生产 Mac 默认数据根不额外添加 `--data-dir`，避免把默认 Keychain 作用域变成隔离作用域。Windows 关闭延迟展开并处理百分号及路径引号；Mac 使用 POSIX 单引号转义。引号规则参照 [Microsoft cmd 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd)，再以受控记录程序实际核对参数。

另存先写独占暂存、flush，提交前再核对原文件未被其它程序改变；覆盖时将当前原文写到 `.bak` 后发布。取消/失败清除本次暂存，原脚本保留。`.bak` 是最近一次原文备份，不是所有历史版本；极晚发布失败时可能已更新 `.bak`，但原文件仍保持。Mac 可执行权限由平台分支设置，Windows 无 Unix chmod。

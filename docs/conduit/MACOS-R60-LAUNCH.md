# R60：启动进度与游戏窗口交接（2026-11-14）

本轮在 `features/windows-parity`、基线 `158dc4e` 上修复启动器过早结束进度的问题；R60 本地验收结束时没有提交、推送或发布。2026-11-15 按用户要求将补丁提交交接，Windows 真机复核见 todo 的 R61 项。Mac 补丁候选为 `MACOS-R60-LAUNCH-20261114/rc2`，个人安装仍为已发布的 v1.6.1，验收后已重新打开。

## 原因与测量

原实现将 `ProcessRunner.StartAsync` 完成私有参数交接视为启动操作完成，随后清空 `LaunchActivity`，首页进度消失。游戏此时还在初始化 JVM、Fabric/Mixin、模组和图形窗口。原有窗口观察仅用于 Windows 改标题，异步结果没有参与加载界面；Mac 路径直接返回 false。最小化、隐藏和关闭策略也在进程交接后立即执行。

现有个人日志可定位到：19:08:39.685 Java 交接，19:08:40 Fabric 加载 215 个模组，19:08:49 LWJGL、19:08:50 OpenGL 初始化。代码中未发现人为增加十几秒的固定等待。WPF 原实现的 `McLaunchWait` 则持续等待 watcher 离开 Loading，再执行启动结束处理。

本轮两次隔离测试均使用 XPlus v6.1.3 / Minecraft 1.21.1 / Fabric 0.18.4、Temurin Java 21、4096 MiB、1000×650 游戏区域、离线角色和同一份隔离缓存。不复制个人账户或世界，不连接服务器。

## 实现

- 启动准备操作和后台窗口观察分离，Java 交接后释放全局操作锁；按 PID 保留启动进度，旧窗口的回调不能清除较新一次启动。
- Mac 使用 CoreGraphics 的目标 PID、普通窗口层级、可见窗口范围和透明度确认实际窗口，排除微小 AWT 辅助窗口。只查询元数据，不读取标题或像素、不申请屏幕录制/辅助功能权限。参见 [Apple 窗口列表接口](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)) 与 [必需元数据键](https://developer.apple.com/documentation/coregraphics/required-window-list-keys)。验收工具的截图/键鼠回退单独取得用户当轮授权，不是产品运行条件。
- 等待阶段显示初始化状态和秒数，下载文件百分比与游戏初始化分开。原取消按钮在参数交接后变成“返回启动器”，仅收起进度，不停止游戏；允许继续使用、同包多开和关闭启动器后游戏继续。
- 最小化/隐藏/关闭在确认窗口后执行；最后一个可见游戏退出、另一个仍在初始化时，隐藏的启动器恢复。窗口观察不设固定秒数的“启动成功”截止；窗口出现、进程退出或启动器关闭会结束观察，查询失败保留“窗口尚未确认”的状态，不终止游戏。
- 分别记录准备、账户/参数、Java 交接和首窗耗时，持续时间使用单调时钟；保留私有 stdin 参数交接及原有凭据组件。
- Windows 继续使用原 Win32 窗口和标题路径；新增 Mac 查询仅在 macOS 执行。共享进度逻辑按相同窗口信号结束，未修改 JVM、模组、认证、下载或 Windows 凭据读取逻辑。

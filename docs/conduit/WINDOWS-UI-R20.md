# R20：旧实例接入、图标与实例列表（2026-11-08）

## 尚未接齐的功能

- **旧实例完整兼容**：本轮覆盖本机 33 个版本的公开身份、继承链、原图标及安全展示偏好；未宣称所有旧版全局/实例 Java、隔离覆盖、渲染器、任意 JVM 参数、前置命令与私有认证字段都已迁移。现有新侧 Java/内存/启动选项继续保留。特殊历史结构、原目录更新后重新接入/映射维护、旧→新→旧的完整高级设置仍须逐项核验。
- **实例管理**：明确停止入口、受验证的脱离会话控制、启动脚本导出尚未接齐；组件修改的更多加载器及格式、第三方启动器导出互认仍待完善。本轮不调用游戏，不把列表接入当作游戏启动成功。
- **资源管理**：模组批量更新/来源识别、完整冲突依赖图；资源包/光影启用和排序；存档数据包的更新/删除/排序；原理图格式及预览等，仍按 todo.md 的 P55–P65 跟进。
- **其它页面**：在线皮肤上传/披风穿戴、收藏页完整缩略图/失效资源、反馈提交、下载来源编辑与完整失败回退等仍有缺口。完整七语、视频背景、自动更新及新增许可清单已取消，不重新列为待办。
- **平台验收**：macOS 原生、完整 DPI/跨屏/高对比度/屏幕阅读器、SMB 断连和所有键盘组合仍未完成。交叉构建不能代替 Mac 原生。本轮窗口检查使用零账户独立数据目录，禁止启动 Minecraft。

## 本轮变化与兼容边界

共享 Core 增加整目录预检和一次事务接入：支持所选 `.minecraft`、`versions` 或单实例目录；每个版本独立核对元数据与继承链，损坏项列出原因，不拖垮其它有效实例。确认前重新读取，批量写入失败/取消不登记一半；已登记版本路径去重，原目录不搬动、不覆盖、不删除。

使用公开 Maven 坐标及现代 Forge/NeoForge 的明确 FML 身份字段识别加载器，不从整合包名称或图标猜测。继承子档使用合并后的库；本地身份同时绑定版本目录与 JSON 哈希，防止相同 JSON 的不同目录折叠。未知 FML 身份拒绝为问题项，不伪装成原版。

仅白名单读取 `PCL/Setup.ini` 的 Logo、IsStar、CustomInfo、DisplayType、VersionLaunchCount 以及 `PCL/Logo.png`。旧内置图片名映射到独立图片资源，任意 URI/图片路径不跟随。用户图标优先，APNG 只显示完整默认画布的静态帧；CRC/大小/解压预算保留，账户皮肤/披风仍拒绝动画。源 INI/PNG 保持原样。

实例列表、概览和首页长名称统一单行省略，完整名字在 tooltip 和可访问名称中保留。左侧补齐独立 Lucide 操作图标，目录路径不再换行；实际 Minecraft 版本和加载器标签替代内部 local 身份。目录、分类、收藏和搜索可组合过滤，不暗中更换持久化选中的实例；收藏优先排序，旧隐藏分类须显式选择。过滤条件仅保留当前会话，目录列表从已保存的来源恢复。

选择本机 PNG/JPEG/WebP/BMP 后可方形裁剪，提供拖动、缩放、横纵位置、90°旋转和复位；最终生成 256×256 PNG，去除原图元数据。自定义图标以内容 SHA-256 存于 `LocalDataDirectory/instance-icons/`，与程序位置和平台无关，macOS 应用包内不写入。配置写前备份、未知字段合并；只在原子提交成功后选用，取消/失败清除本次新增图标和暂存，原图及旧图标保持，可切换回自动或旧内置图标。新图标不会写回旧 WPF 的 PCL/Logo.png。

额外补齐 LiteLoader `.litemod` 的本地导入和启停；其它加载器拒绝不兼容 `.litemod`，OptiFine/LabyMod 不被误当成支持普通模组目录。此项不代表完整模组来源、更新和依赖管理完成。

## 实测

只读核对用户指定的 `E:\Minecraft\.minecraft`：33 个版本全部预检并接入，5 个原版、13 个 Fabric、9 个 Forge、1 个 NeoForge、5 个 OptiFine；本机未覆盖的其它加载器由受控坐标/继承回归覆盖，不算真实运行。两个 `PCL/Logo.png` 分别为 Reflection Modpack 静态 PNG 和 Simply Optimized APNG，均能显示；其余实例使用原先保存的内置图标或实际加载器图标。

服务验收先改新侧显示名、分类、收藏及图标，再销毁并重建服务读取；自动/自定义图标切回、未知字段和选中状态均保留。图标已经发布、配置仍待提交时触发真实文件系统取消，配置和旧图标集合不变；另一轮持有 Windows 配置文件只读句柄造成提交失败，同样回滚。批量接入另有预取消、源 JSON 变化、重复候选与保存失败测试。最后核对 68 个原 JSON/INI/PNG 文件哈希不变，图标暂存为 0；服务的 Run/Start 均由拒绝实现接管，调用数为 0。

Windows 原生为 200% DPI、976×636 DIP（1952×1272 像素）、零账户独立目录。实际确认侧栏图标、长名称单行省略、旧图标、NeoForge 身份、目录/收藏/搜索；从原生文件选择器打开有中文及空格的受控图片，操作缩放、位置、旋转、取消，再次打开裁剪并保存。取消保留原 SHA-256；保存后为新的 256×256 PNG，再由实际改名弹窗保存长名称。新配置的备份存在，源图片哈希不变。

关闭并重新打开最终 RC2，列表实际显示新名称、红色受控裁剪图标及原 Fabric 标签；33 个实例、分类、收藏、选中实例、未知字段与图片哈希再次核对。RC1、RC2、RC2 重启三次正常关闭均为 exit0、无外层超时；无候选进程残留。重启阶段有受其它窗口遮挡的补充截图，已剔除并重取列表截图；没有据此声称最小尺寸、深色或完整键盘矩阵通过。Computer Use 截图两次超时后按既有明确授权使用原生备用接口，并增加截图前后前台一致性检查；没有操作认证/系统授权界面。

代表证据：`reports/r20-rc2-selection.png`、`r20-ui-simply.png`、`r20-ui-reflection.png`、`r20-rc2-neoforge.png`、`r20-rc2-crop-initial.png`、`r20-rc2-crop-saved.png`、`r20-restart-confirmed.png`。SO/Reflection 原生截图来自 RC1，其公开旧图标读取在最终服务矩阵中再验；最终新图标及重启截图来自 RC2。详见 `r20-native-third.json`、`r20-ui-restart-audit.json`、`r20-final-audit.json`。

## 回归与首次失败

Core 最终 543 通过 / 16 显式跳过 / 0 失败，总计 559；相对 R19 新增 28 项。跳过原因为 8 项原生链接/POSIX 与 Windows reparse 专项、4 项 macOS 原生（Keychain 3、argv 1）、2 项显式 Java 修复副本门禁未启用、1 项受控 POSIX 失败子进程、1 项 OnlineJava 未启用。未通过启用在线/Java/游戏测试来消除跳过。

Desktop 最终 **188 通过 / 0 跳过 / 0 失败**，相对 R19 新增 8 项。含真实控件长名/图标布局、目录/分类/收藏/隐藏状态、显式批量确认、失败保留预览及裁剪取消/失败。最终 Win-x64 自包含 Release 和 osx-arm64 Release 交叉构建均为 0 警告、0 错误；后者未运行，Mac 原生待验。

首次编译失败分别为跨程序集内部 API/构造器及 ListBox 的无效属性；已改为图标专用像素模型、公开路径守卫和 ListBoxItem 样式。首次 Core 的两项失败是 Windows 配置目标被目录占用返回 UnauthorizedAccessException，拒绝帮助器漏接；补接异常后仍核对原配置与图标不变。首次 Desktop 的旧导航测试捕捉到瞬时空 DataContext 绑定；改为控件从视图上下文取得图标服务，未压掉绑定错误。

首次真实旧目录检查暴露现代 FML 被误分类及 APNG 图标被拒绝，已补明确身份读取和安全静态帧。RC1 原生窗口再发现图标错误存放程序目录，随后修至用户数据目录并加入更换程序位置的回归；RC1 已被 RC2 取代。首轮失败日志、TRX 和报告均保留。

# 稳定的 macOS 凭据组件

`credential_broker.c` 是单次请求的原生 Security.framework 客户端，不是常驻服务。
维护者签名的 Mac 应用通过匿名管道调用它，原有 service/account 键和凭据内容保持不变。

## 为什么保留固定产物

自签程序在当前登录钥匙串中按 cdhash 分区。主程序每次编译/打包的 cdhash 都可能变化；
单纯复用证书不能阻止这类授权提示。组件的完整签名二进制固定保存于 `frozen-arm64-v1/`，
普通打包仅核验源码/二进制 SHA-256、签名者和签名完整性，再原样复制到应用 `Contents/Helpers`。
不要在普通发布过程中重编或重签该文件，主程序版本、构建机和 SDK 的变化不应改变它。

`manifest.json` 记录源码与产物哈希、cdhash、签名身份、编译器、SDK 和最低系统版本。
Git 对二进制禁用文本转换，对源码固定 LF；文件只包含公开代码签名证书，不含签名私钥。
需要修改组件本身或迁移签名身份时，明确执行：

```sh
python3 scripts/macos/build_credential_broker.py
```

这会使用已配置的本地身份（或明确提供的 CI 签名身份）重新编译并签名。
组件自身或签名身份的变更可能需要用户重新授权，不能将它混入普通 UI 更新而宣称仍是同一凭据组件。

## 访问边界

- 组件只接受同一证书签名、标识精确为 `club.conduit.shou.launcher` 的直接父进程。
  校验运行中的父进程，并验证完整应用包及嵌套代码，包含托管程序集和资源；收到请求后再次核验。
- 主程序在发送任何凭据前验证运行中的子进程：证书相同、标识精确为
  `club.conduit.shou.launcher.credentials.v1`，且启用 hardened runtime。
  组件没有 JIT、调试或关闭库验证等例外 entitlement。
- 数据只经过匿名 stdin/stdout 管道；不出现在 argv、环境变量、临时文件或日志。
  消息长度受限，临时输入和响应缓冲区在使用后清理；错误不回显凭据。
- 仅支持启动器既有 service 和明确隔离的 service；不提供任意钥匙串、任意程序运行或网络接口。
  没有全局 ACL 修改、系统信任修改、登录钥匙串解锁密码或明文凭据后备。
- 后台读写禁止系统交互；仅既有“重新授权钥匙串”入口的读取请求允许系统交互。
  普通请求 30 秒、显式授权 5 分钟上限；取消时主程序终止自己的子进程，原生组件也有独立超时。
- 固定签名的完整应用缺少组件或子进程身份不符时失败，不退回旧后端继续写入。
  未打包开发宿主及明确标注的 ad-hoc PR 测试包保留原适配器，不宣称具备同等升级免授权效果。

## 验证

`scripts/macos/test_credential_broker.py` 验证冻结产物与源码、不同 cdhash 的可信调用者读写、
无关签名/不同应用/父资源篡改/无关 service 拒绝，并删除模拟项与签名测试程序。
`scripts/macos/test_packaged_credentials.py` 对真实候选的更新副本验证读写和故障：
资源或托管程序集篡改、组件缺失、冒充组件均拒绝；冒充组件收到的请求/凭据字节数必须为零。
本机使用唯一隔离命名空间；GitHub CI 使用临时测试钥匙串并恢复默认钥匙串和搜索列表。
这些测试不读取真实账户、不弹授权、不启动游戏，也不会留下测试应用到发行目录中。
